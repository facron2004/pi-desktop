# 多会话业务审查与优化

审查日期：2026-10-29。对象：当前 Pi Desktop v0.5.0 工作区，含审查开始前已有的未提交多会话实现。修复基于现有改动叠加，未重置工作区。

## 结论与使用边界

当前已验证支持多个会话独立运行、后台更新和独立停止：

| 场景 | 行为 |
| --- | --- |
| 不同工作目录 | 可同时运行，各自拥有 Pi 进程 |
| 同一目录的多个聊天 | 任务排队，前一个真正结束后再执行下一个 |
| 浏览项目、切换聊天、搜索跳转 | 只切换视图，不中断后台任务 |
| 多个会话同时等待批准 | 分别保存请求，回复只发给对应进程和 Pi 请求 ID |
| 停止当前或侧栏指定会话 | 只影响目标会话 |
| 关闭或移除项目 | 停止该目录的任务，其他目录继续 |
| 分叉或复制 | 新会话与原会话保持独立身份，原会话可重新启动 |
| Git 写操作 | 与任务共用目录锁，避免后台任务执行中切分支或回滚 |
| 退出应用 | 等待 Pi 清理并退出；正常退出超时才强制结束 |

同项目需要真正并行修改时，应使用不同 worktree。锁按实际工作目录识别，不是跨应用、跨进程的文件锁；外部编辑器、外部终端和不同目录对同一个外部文件的操作不在这把锁的覆盖范围。

## 发现并修复的问题

| 优先级 | 原问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 发送等待进程启动时重新读取当前视图，可能把消息发到切换后的聊天；停止清队列后也可能中止另一个聊天 | 捕获操作归属，所有后续 RPC 和状态写入绑定原会话 |
| P1 | 后台会话结束时调用前台刷新，延迟状态响应可把视图切回旧会话 | 状态、历史、分支点和命令刷新显式携带归属；模型、模式、推理选项按会话保存 |
| P1 | 目录队列的键与锁的键不一致；停止先删除进程，导致无法释放锁；非持有者、已处理命令或失败的追加指令又可能提前放行 | 统一路径身份，记录在途写请求和运行状态；确认进程退出后释放；取消、完成和异常走同一队列路径 |
| P1 | 直接 bash 完成不产生 agent_settled，目录可能一直被占用；清队列只清了 Pi 内部队列 | bash 响应后释放自身占用；同时处理桌面目录队列的取消与消息恢复 |
| P1 | 分叉后把原 JSONL 永久别名到分支，重开原会话仍落到分支；旧闲置定时器也可能停止重开的原会话 | 保留原会话缓存与文件身份；只保留草稿及同文件拼写别名；重新绑定闲置定时器 |
| P1 | Git 切分支、回滚、补丁、索引等写入绕过运行目录锁；空闲前台掩盖后台写入者 | 主进程统一互斥，移除 worktree 同时检查目标目录 |
| P1 | Electron 的异步 before-quit 没有阻止退出；CLI 在 stdin 关闭后又被立即终止，无法完成正常清理 | 阻止退出直至所有会话停止；先等待 EOF 清理，超时强制结束；停止确认后清除假运行状态 |
| P2 | 终端按旧的裸事件格式订阅，收不到带归属的流式输出；切换聊天后停止/关闭终端可能发往其他会话 | IPC 事件契约显式包含归属；终端保存命令的原会话，启动期间取消也不会补发命令 |
| P2 | 保存供应商会修改第一个热进程，而非当前聊天；恢复历史又会被全局默认模型覆盖 | 仅对明确选中的空闲会话应用供应商；历史模型和推理设置交给 Pi 恢复 |
| P2 | 每帧仍逐条发布文本增量，后台会话增多时引发多次订阅通知和正文更新 | 每会话每帧合并发布，重复生成状态不再重复写入；运行时归属查询改为直接查找 |
| P2 | 冷会话的导出、分叉、模式等动作没有对应进程；未落盘会话重启后仍向旧路径发命令；启动失败仍可能报告连接运行中 | 显式动作按需启动自己的进程；区分启动替换与分叉，更新在途操作的目标；覆盖启动/停止竞态与失败连接 |

另修复基线中已有的两处输入模态集合推导错误，使 node/web 类型检查通过，未改动相关模型配置行为。

## 验证与复现

- 基线：98 项测试通过；类型检查存在两处错误。新增的第一批 17 项并发回归测试在修复前全部失败。
- 最终：`npm test` 136/136 通过，`npm run typecheck`、`npm run build`、`git diff --check` 通过。
- 真实运行：31/31 检查通过，使用生产 renderer、Electron main/preload、随包 Pi CLI，以及本地 SSE 模型服务；11 次本地推理请求，不使用付费模型账号。
- 覆盖跨目录同时运行、同目录排队、后台停止与 Git 保护、bash 释放、冷历史与模式恢复、分叉身份、供应商目标、终端实时输出与停止、两会话工具审批、移除后台项目和带任务退出。
- 退出验证同时检查全部记录到的 Pi CLI PID 已消失，未发现 renderer 异常或 destroyed-window 错误。
- 性能回归：100 个同帧文本增量，正文只发布 1 次更新，内容完整保留。

## 尚未量化的容量边界

- 当前是一热会话一进程，闲置约十分钟回收。本轮验证两个目录同时推理、两个目录同时等待审批；未进行几十个热会话的内存/CPU容量测试，也未验证真实供应商的并发限流。
- 历史列表、搜索和统计仍有主进程同步文件读取。长历史和大量会话的磁盘扫描属于下一轮性能测量重点，本轮没有据此声称大规模流畅性。
