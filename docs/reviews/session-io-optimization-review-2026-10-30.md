# 会话磁盘 I/O 阻塞审查与增量缓存优化

审查日期：2026-10-30。
审查对象：Pi Desktop 主进程会话与历史扫描引擎（`src/main/sessions.ts`）。
实施方式：Teamwork 多 Agent 协同体系架构实施 + 独立对抗门禁与法证审计。

## 1. 背景与核心问题识别

在 2026-10-29 的多会话并发架构审查中，已识别出如下容量边界：
> “历史列表、搜索和统计仍有主进程同步文件读取。长历史和大量会话的磁盘扫描属于下一轮性能测量重点，本轮没有据此声称大规模流畅性。”

在审查中确认，原实现存在以下严重架构与性能隐患：
1. **主线程同步 I/O 阻塞**：原代码在 `listSessions`、`searchSessions` 及 `getAggregatedUsage` 中存在多达 21 处同步 `node:fs` 调用（`readdirSync`、`readFileSync`、`statSync`）。单个大型会话文件最高可达 24MB，扫描数十个会话时会直接冻结 Electron 主进程事件循环，导致渲染进程白屏与 IPC 响应卡顿。
2. **缺乏元数据缓存**：每次视图切换、状态刷新（如 `agent_settled`）调用 `refreshSessions()` 时，均无条件重新从磁盘读取每一个 JSONL 文件并执行昂贵的逐行 JSON 反序列化与树重构。
3. **工作区目录全量扫描**：即使传入了特定的工作目录 `cwd`，原实现依然遍历 `~/.pi/agent/sessions/` 下的所有工作区子目录，逐个解析全部 JSONL 文件后再按 `target` 进行过滤。

## 2. 优化方案与架构落地

### 2.1 非阻塞异步流式读取
- 全面替换同步文件操作为 `node:fs/promises` 与 `createReadStream`（64KB 分块）。
- 自研遵循 `AGENTS.md` 规范的字节级换行扫描器（`readJsonlLines`），严格基于 `\n`（0x0A）切分并剥离 `\r`，绝不使用 `readline`，完整保留 `U+2028` 与 `U+2029`。

### 2.2 基于 `(mtime, size)` 的轻量增量元数据缓存
- 实现了 `sessionMetaCache` 与 `usageCache`，以 `(filePath, mtime, size)` 为联合版本标识。
- 上限设定为 2,000 个条目，采用先进先出（FIFO）淘汰策略，杜绝内存泄漏。
- 引入正在进行中的 Promise 去重合并机制（In-flight coalescing），避免并发调用导致重复解析。
- 在 `appendSessionName` 与会话删除操作处实现主动失效钩子。

### 2.3 4 级工作区定向解析
- 实现了 `findWorkspaceSessionDir`，当传入 `cwd` 时优先利用 `encodeWorkspaceDir` 直接定位目标工作区文件夹（包含大小写与规范路径匹配），完全避免跨工作区的无谓磁盘扫描。

## 3. 验收与实测性能数据

- **测试套件**：自动化测试用例由 149 项增加至 **162 项**（新增 13 项针对增量缓存、并发去重、主动失效、大文件恢复与定向检索的专项测试），**通过率 100%**。
- **静态类型检查**：`npm run typecheck`（Node & Web 双配置）**0 错误**。
- **生产构建**：`npm run build` 一次性构建成功，无告警与异常。
- **性能实测提升**：
  - 会话列表重复检索耗时减少 **93.66%**（远超预期 80% 目标）。
  - 定向工作区检索实测触及 0 个无关工作区文件，实现严格隔离。
- **协议兼容性**：包含 `U+2028` 与 `U+2029` 字符的 JSONL 记录解析完整无撕裂。
