# Pi Desktop v0.11.9

## 更新内容

- **检查更新图标**。侧栏「设置」旁换成一枚强调色实心圆钮，里面始终是下载图标，圆内的进度环按真实字节滚动。下载并校验完成后圆环闭合，同一个位置点一下就重启安装——不换图标、不换配色，满不满一眼就能看出来。下载与安装是两步：后台只负责把安装包取回并校验，不打断任何正在运行的会话或任务；安装包留在 `updates/` 里，重启应用仍显示「可以重启安装」，不会重复下载同一个版本。复用缓存和真正安装前都会重新核对 SHA-256，被强杀留下的下载暂存目录会在下次下载或下次成功检查时清掉。
- **「自动检查更新」对安装版开放**。设置 → 关于页的自动检查开关不再只画在开发入口：安装版也可以选择在后台检查并下载新版本，关闭后只有手动「立即检查」和帮助菜单访问 GitHub。检查失败不会抹掉上一次查到的新版本——无论是侧栏图标还是关于页。
- **内置服务版本单独检查**。内置 Pi CLI 是应用驱动的 agent，版本过旧不是「少了个功能」，而是答错，所以它按自己的时钟检查：开发入口启动时与每 12 小时各一次，与「自动检查更新」开关无关；安装版从本地文件回答，不联网。顺带修掉一个把启动结果丢掉的问题：启动时 `info` 与设置到达会重建调度 effect，旧代码在这个窗口里把已经回来的答案丢弃，于是即便真的查到了新版本，关于页也一直什么都不显示。
- **用量趋势改为最新在前**。设置 → 用量的「近 7 天每日消耗趋势」把今天排在第一行，打开就能看到最近一天花了多少，不必滚到表底。数据仍按时间正序存放，热力图照旧按日期取值，只有这张表的显示顺序反了过来。
- **外观主题预设**。六套主题各自使用产品自己的强调色与画布色。此前「ChatGPT」与「Claude」写的是同一块陶土色、两块画布只差一个色阶，「Pi」与「GitHub」写的是同一个纯白画布——四套外观其实只有两种样子。颜色集中到 `src/shared/theme-presets.ts`，由测试保证每套的强调色与画布色互不相同；外观页按这一份数据重排。
- **发送与草稿**。发送由 store 统一受理（`submitComposerDraft`），按会话记录「正在提交」，取代组件里那份会跟着会话切换错位的锁。已提交的草稿在 Pi 接受之前继续留在输入框与磁盘上，接受后只清掉仍是这一次提交的那份内容——等待期间继续敲进去的字不会被抹掉。
- **Git 面板绑定项目目录**。分支菜单、评审面板、差异视图和改动摘要的读取与写回都带上目标项目的根目录。从一个项目切到另一个项目时，不再可能把上一个项目的 diff、回滚或撤销套到当前项目上；晚到的旧请求也不会覆盖新项目的读数。
- **对话框内的菜单层级**。从设置页这类全窗口对话框里打开的下拉菜单，原先被画在对话框卡片后面（portal 到 `body` 之后拿不到对话框的层级），现在检测到自己处在一个 `.modal-layer` 内就提升到对话框之上。
- **侧栏归档分组**。单列表模式下归档会话不再混在普通会话里，而是统一放到底部并按项目分组显示标题——那一列本来没有项目行，归档行最容易看不出属于哪个目录。
- **删除单条记忆需要确认**。记忆页的删除图标不再点击即生效，而是先问一句，并引用这条记忆自己的文字（截断到 120 字），避免在一列相似条目里点错就永久丢失。
- **长期存放的文件会自愈**。`scheduled-tasks.json` 读不出来时改名成 `scheduled-tasks.corrupt-<时间戳>-<id>.json` 并从空列表继续，不再因为锁死指纹让定时任务页永久空白；记忆的 `rollout_summaries/` 限制在 200 个文件 / 8 MiB，超出时优先删除最旧的，单条超过整体预算时只丢它自己。
- **快捷键保存基线**。改快捷键时把当前已保存的绑定一起提交，连续快速修改不会因为读到旧快照而互相覆盖。

## 发布说明

- 本次发布由 GitHub Actions 从 `v0.11.9` 标签构建，产物与本机 `npm run dist` 一致。
- 应用内更新读取 `releases/latest`，请保持该 Release 不是草稿、不是预发布，否则旧版本收不到更新提示。
