# 前端优化方案与验收

日期：2026-10-20。执行模型：`gpt-6-luna`，主代理负责审查与最终验证。

## 目标和边界

沿用当前 Electron / React / Zustand 架构和主题，在现有界面中改善流式回复、输入、搜索、窄窗口及键盘操作。不新增产品功能、依赖或设计系统，不改 Pi 协议、主进程和 IPC 契约，不做大规模文件拆分。

已有未提交改动必须保留：`FileViewer.tsx`、`InspectorPanel.tsx`、`ToolCard.tsx`、`Welcome.tsx`、`global.css`、`lib/diff-text.ts` 及 `docs/shots/168.png`、`169.png`。本次只允许在 `global.css` 上叠加布局规则，其余上述文件不纳入修改。

## 现状依据

- 基线 `npm run typecheck`、`npm run build` 通过。渲染器入口 JS 为 1,325.59 kB；Shiki 语法与引擎已经按需加载，本轮不以拆包为目标。
- `Markdown.tsx` 在每次渲染中定义 `components`，导致组件类型随流式文本更新变化。Electron 注入同一回复的 8 次增量，已有代码块 DOM 被替换 8 次。
- `App.tsx` 订阅完整 `items`，大多只判断是否有消息；`useLauncherActions` 为点击复制时才用到的消息订阅了整条流。
- `Thread.tsx` 在搜索未打开、查询为空时仍遍历消息构建全文索引。
- `Composer.tsx` 的输入法保护位于候选选择逻辑之后；文件提及请求缺少失败处理和工作区依赖，候选键盘选择没有同步滚动。
- `FileTree.tsx` 的搜索依赖没有工作区根目录，切换项目时缓存和异步结果需要隔离。
- 1080px 窗口、272px 侧栏、420px 检查器同时显示时，会话仅余 388px。允许的面板最大宽度还会进一步挤压正文。
- 快捷键、设置及确认弹窗没有完整的对话框语义和焦点管理。实测快捷键弹窗打开后焦点没有进入弹窗。

## 复核方式

1. 对比最初 dirty diff，确认原有功能和文件未被覆盖；`git diff --check`。
2. 执行 `npm run typecheck`、`npm run build`。
3. 用实际 Electron 渲染器和独立 userData 目录复验流式代码块、搜索、代码 Ask、中文输入、文件候选及弹窗焦点。交互边界使用可控数据或异步响应夹具，不发起付费模型推理。
4. 检查 1080px / 1480px、浅色 / 深色截图，验证有正文、无框架错误层和新增控制台错误。
5. 临时脚本、日志、截图保存到仓库外的本次可视化目录，不提交生成构建产物或测试报告。
