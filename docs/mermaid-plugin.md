# Mermaid 图表插件

把 Pi 的 Mermaid 能力补成产品经理可以直接使用的一套东西：模型知道该画哪种图、怎么画得可读，Pi Desktop 把 ```mermaid 代码块真正渲染成图，输入框里还有一组产品经理常用的图表模板。

## 组成

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 渲染层 | `src/renderer/src/components/MermaidDiagram.tsx` | 把 Markdown 里的 ```mermaid 代码块渲染成 SVG；缩放、适应宽度、全屏、源码切换、复制与下载 SVG |
| 模板层 | `src/renderer/src/lib/mermaid-templates.ts` | 13 个产品经理图表模板，解释每个模板适合什么场景，并把完整提示词插入输入框 |
| 提示层 | `src/main/pi/mermaid.ts` | 每个 Pi 进程都会加载的轻量扩展：只在用户提到图表时追加 Mermaid 作图规范 |
| 插件包 | `plugins/mermaid/` | 可安装到 Pi 的完整插件：`mermaid` 工具（模板 / 校验）、`/mermaid` 命令、`mermaid-diagrams` 技能 |

渲染层和提示层随 Pi Desktop 一起工作，不需要额外安装。插件包提供更完整的模板、语法校验和技能说明，适合把同一套能力带到 Pi CLI 或其他客户端。

## 使用

### 在 Pi Desktop 里直接画图

在对话中让 Pi 输出 Mermaid，例如：

```text
画一个跨部门的退款审批泳道图，包含客服、财务、运营三个角色。
```

回复中的 ```mermaid 代码块会自动渲染为图。工具栏从左到右是缩放、适应宽度、全屏、源码/图形切换、复制源码、下载 SVG。

输入框的 `+` → **图表** 提供 13 个模板：

| 模板 | 适合场景 |
| --- | --- |
| 业务流程图 | 从请求到结果的步骤与判断分支 |
| 跨职能泳道图 | 角色/部门之间的交接与责任边界 |
| 时序图 | 用户、系统、服务之间的交互顺序 |
| 状态机图 | 订单、订阅、工单等生命周期 |
| 用户旅程图 | 分阶段的体验、情绪与痛点 |
| 甘特图 | 版本计划、依赖关系和里程碑 |
| 思维导图 | 问题、范围、机会的层级拆解 |
| 路线图时间线 | 按季度/月份讲发布故事 |
| 优先级象限图 | 影响 × 成本、紧急 × 重要 |
| 需求图 | 需求、风险与验证方式 |
| 看板图 | 待办、进行中、评审、完成 |
| 系统架构图 | 按客户端/接入/服务/数据分层 |
| 饼图 | 投入、流量等单一口径占比 |

点一个模板会把完整提示词放进输入框，替换掉占位内容即可发送。提示词要求 Pi：只输出一个 Mermaid 代码块、标签短且动词开头、判断分支写条件、不超过 20 个节点、信息不足时先做合理假设。

### 安装完整插件包

插件包是标准的 Pi package（`pi-package`）：

```bash
# 在 Pi Desktop 仓库根目录
pi install ./plugins/mermaid

# 或在应用内：插件与技能 → 安装 → 本地路径 / npm / GitHub
```

安装后：

- `mermaid` 工具：
  - `action: "template"`，`template: "swimlane"`，`title: "退款审批"`：生成可直接修改的 Mermaid 起步代码；
  - `action: "check"`，`source: "flowchart TD ..."`：返回语法检查结果、错误行号和修复建议，并在支持的类型上附带 Unicode 预览。
- `/mermaid` 命令：在 TUI 中选模板、填主题，自动把完整作图请求发给 Pi。
- `mermaid-diagrams` 技能：产品经理图表选择、泳道图写法、常见语法陷阱和质量检查清单。

## 图表选择

选择图表时先问“读者要做的决定是什么”，再选最小的能回答它的图：

| 读者的问题 | 用 |
| --- | --- |
| 这项工作怎么从请求走到结果？ | `flowchart TD` |
| 每一步是谁做的、在哪里交接？ | `flowchart LR` + 每个角色一个 `subgraph`（Mermaid 没有原生泳道） |
| 谁在什么时候给谁发了什么？ | `sequenceDiagram` |
| 一个对象有哪些状态、如何流转？ | `stateDiagram-v2` |
| 用户在每个阶段体验如何？ | `journey` |
| 什么时候做什么、依赖是什么？ | `gantt` |
| 一个问题能拆成哪些部分？ | `mindmap` |
| 版本按时间怎么走？ | `timeline` |
| 先做哪个？ | `quadrantChart` |
| 需求如何被满足和验证？ | `requirementDiagram` |
| 工作现在堆在哪一列？ | `kanban` |
| 系统由哪些层和组件组成？ | `flowchart TD` + 分层 `subgraph` |
| 总量如何拆分？ | `pie` |

## 产品经理作图规范

- **先主路径，再异常。** 一张图只讲一个故事，异常分支放旁支。
- **标签动宾化。** “提交申请”而不是“申请提交”；判断边写条件（`|金额>10万|`）。
- **控制规模。** 20 个节点以内；超过就拆成两张图，或在图后用文字补充。
- **中文直接写。** Mermaid 支持 UTF-8；标签里有括号、逗号、冒号、箭头时加双引号：`A["提交申请（含附件）"]`。
- **结构闭合。** 每个 `subgraph` 都要有自己的 `end`；不要把 `end` 当节点名。
- **少即是多。** 不加无意义的颜色和图标；用分组、标题和说明表达重点。节点统一用圆角矩形，只有判断用菱形，开始/结束才用圆形或胶囊形；一个强调色只留给判断和异常。

## 视觉风格

渲染器会按 Pi Desktop 的深浅色主题统一给图表上色，插件生成的 Mermaid 源码不需要手写 `classDef`、`style` 或 `%%{init}%%`：

- 普通步骤使用主题的中性面，判断节点带强调色，风险/阻塞最多再用一个颜色。
- 每个节点标签控制在 8 个词以内；泳道标题用名词，流程节点用动词。
- 分组只表达责任或层级，不套三层以上；宁可拆成两张图，也不要堆成一团。
- 同一张图不超过 20 个节点，主路径保持一条清晰的视觉动线。
- 不使用 emoji 或装饰图标；不手写颜色，以免在浅色/深色主题下失去对比度。

## 常见语法陷阱

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 标签把节点撑坏 | 标签里有未转义的括号 | `A["退款（含手续费）"]` |
| 图只画了一半 | `subgraph` 缺少 `end` | 每个 `subgraph` 补 `end` |
| 判断分支没有标签 | 只写了箭头 | `Decision -->|通过| Next` |
| 甘特图报错 | 缺少 `dateFormat` | 头部后加 `dateFormat YYYY-MM-DD` |
| 思维导图层级不对 | 用空格数而不是每级一次缩进 | 每层只缩进一次 |
| 序列图参与者未声明 | 先用了别名 | 先 `participant API as 订单服务` |
| 标签里的 `<` `>` 被当成 HTML | 原始尖括号 | 用 `#lt;` / `#gt;` |

## 开发与验证

```bash
npm run typecheck       # 主进程 + 渲染进程类型检查
npm test                # 单元测试（含 Mermaid 模板与校验器）
npm run build           # 生产构建
```

渲染层使用 `mermaid@11`，按需动态加载；首次出现图表前不会把解析器加载进渲染进程。渲染失败时保留上一版可用 SVG，并显示错误与源码，绝不让一张写坏的图影响整段对话。

插件包的测试在 `tests/mermaid-plugin.test.ts`，覆盖校验器的常见错误和 13 个模板的 `buildTemplate` 输出；每个模板都必须通过 `validateMermaid`。
