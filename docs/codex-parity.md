# 与 Codex 的功能对齐：路线图

更新：2026-10-20。目标是让 Pi Desktop 的前端在交互上尽可能接近 Codex 桌面端，
同时不偏离本项目的边界 —— 它是 Pi 的协议客户端，不重新实现 agent，不改 Pi 协议。

## 已完成

| 能力 | 说明 |
| --- | --- |
| Git 分支状态 | 顶栏显示当前分支、领先/落后提交数、未提交文件数；点击打开检查器 |
| 提交闭环 | Changes 面板的 Commit 打开审阅弹窗：工作区文件、行数统计、提交说明、Ctrl+Enter 提交 |
| Review 审阅 | 检查器第三个标签，直接读 git 工作区：每个文件可展开真实 diff（含未跟踪新增、已删除文件），单文件还原到 HEAD（需确认） |
| 暂存与提交范围 | Review 内单文件 Stage/Unstage、Stage all/Unstage all；Commit 弹窗显示 staged/unstaged，默认只提交已暂存，勾选后才把工作区一并提交 |
| 集成终端 | `Ctrl+`` 打开底部终端，走 Pi 的 RPC `bash`，流式输出、退出码、耗时、Stop、历史、清空 |
| 终端复用命令 | bash 工具卡与 bash 卡片可直接“在终端中运行”，复用同一条执行路径，输出不进上下文 |
| 终端打磨 | 拖动上边缘调整高度并持久化（键盘 ↑/↓ 也可、双击复位）、Ctrl+C 中止、输出过滤（Ctrl+F）；ANSI 颜色解析已就绪，但 Pi 的 RPC `bash` 输出目前是纯文本，颜色只在将来有颜色输出时生效 |
| 计划进度条 | 从 assistant 消息的 markdown checklist 投影出计划条：完成数、当前步骤、可展开列表、可关闭；新计划自动展开 |
| 会话全文搜索 | 侧栏输入 2 个字符后搜索所有会话正文，命中带角色、片段高亮、项目与时间 |
| 搜索跳转 | 点击命中后打开会话（必要时切换项目）、滚动到对应轮次并闪烁高亮，同时打开会话内搜索定位到该词 |
| 会话树 | `Ctrl+Shift+T` 或 `/tree` 读取 `get_tree`：分支点、当前路径、叶子标记；任意用户提示可 Fork，提示回到 composer |
| 项目文本搜索 | Files 标签 Text 模式：按行搜索项目文本（跳过二进制/超大文件），按文件分组、显示行号与命中高亮，点击跳到行 |
| 提交前检查 | Commit 弹窗最多 3 条提示：留滞的未暂存文件、将提交的二进制/未跟踪文件、主题过长/过于笼统/以句号结尾 |
| Review 补丁 | 单文件或整棵工作区的 HEAD→工作区补丁复制（未跟踪文件合成 new file 补丁），可直接 `git apply`；重命名文件显示 `old → new` 并以旧路径内容做 diff |
| 会话树增强 | 过滤（匹配行保留祖先、清除后恢复原折叠）、按会话记住折叠状态、分支末端前后跳转 + 闪烁 |
| 文件阅读器 | 文件内查找（Ctrl+F、Enter 步进、n of m）、行跳转、自动换行（持久化）、复制相对路径/内容 |
| 提交详情 | 历史提交点开查看元数据、文件列表（含重命名旧路径）与单文件 diff，可复制整个提交的补丁 |
| Hunk 补丁 | Review 的每个修改块可复制为独立 `git apply` 补丁（hunk 头、折叠上下文按 git 规则补齐） |
| 计划动作 | 计划条可复制为 markdown 清单、整体放入 composer、单步放入 composer |
| 分支与工作树 | 顶栏分支菜单：切换本地分支、新建并切换、列出并打开 worktree、按新分支创建工作树并切换项目 |
| Hunk 还原 | Review 每个 hunk 可单独反向应用（确认框、失败提示、应用后刷新 diff，索引不受影响） |
| 最近搜索 | 侧栏记住最近 8 条有命中的会话搜索，聚焦空输入时可点击重跑、可清空 |
| 提交历史与模板 | Commit 弹窗列出最近提交（可用标题、复制哈希）、`feat/fix/docs/...` 模板、失败/取消保留草稿 |
| 模型菜单信息 | 每个模型显示上下文窗口、每百万 token 价格（有则显示）、推理与图片能力；推理菜单解释各档位 |
| 图片灯箱 | 会话内图片（用户、助手、markdown）点击全屏查看，含尺寸、保存、Escape/背景关闭与焦点归还 |
| 既有能力 | 流式对话、工具卡/diff、检查器（Changes/Files）、@ 文件、/ 命令、模型与推理切换、上下文面板、分支/fork、导出、扩展弹窗、键盘操作、双主题 |

终端命令使用 `excludeFromContext: true` 与 `terminal-` 前缀的 id：它们留在会话文件里，
但不进入模型上下文，也不出现在对话线程中（thread 的 hydration 会跳过这类 bashExecution）。

## Codex 功能对照

| Codex | 当前状态 | 下一步 |
| --- | --- | --- |
| 分支/工作区头部 | 分支 chip、dirty 数量 | 分支切换、新建分支、worktree |
| Diff 审阅 | 对话内工具 diff + git 工作区文件列表 | 新增基于 `git diff` 的 Review 视图、按文件撤销、按 hunk 暂存 |
| 提交 / PR | 一键提交全部更改 | 提交历史、生成提交说明、gh PR |
| 集成终端 | 底部抽屉，RPC bash，流式 | 面板高度拖动、ANSI 颜色、Ctrl+C、命令历史持久化 |
| 计划模式 | 无 | 读取会话中的 checklist/计划块并渲染为进度列表 |
| 审批 / 沙箱 | 项目信任开关（设置） | 在项目头部提示信任状态，启动前可切换 |
| 会话切换 | 侧栏历史、pin、全文搜索 | 搜索结果跳转到具体消息；会话树（get_tree） |
| 图片 | 粘贴/拖拽附图、模型出图 | 灯箱、缩放、另存 |
| 模型控制 | 模型/推理下拉、Ctrl+P/Ctrl+T | 成本与上下文窗口信息、搜索 |
| MCP / 技能 | 仅 Pi 自身的命令列表 | `.pi/mcp.json` 只读展示与启用开关；技能列表 |
| 快捷键 | 命令面板、快捷键表 | 与 Codex 对齐的默认键位与冲突检查 |

## 下一轮优先级

P0
1. MCP 配置只读面板（`.pi/mcp.json`）：列出服务器、传输方式与启用状态。
2. 提交详情增强：与当前工作区对比、查看父提交、把历史版本文件在查看器中打开。
3. 设置页补齐终端 / 审查 / 通知分区，并允许重置工作树/面板宽度。

P1
4. 计划条：勾选步骤并把 checklist 写回 composer、计划历史。
5. worktree 管理：移除工作树、在分支菜单中显示每个工作树的脏状态。
6. 搜索增强：正则/大小写选项、结果按会话分组。
7. 快捷键自定义与冲突检查。

P2
8. 长会话虚拟列表（需要先测量）。
9. 导出 Markdown、会话分享。

## 验证约定

- 每次改动：`npm run typecheck`、`npm run build`、`git diff --check`。
- 视觉验证用截图 harness：`PI_DESKTOP_SCREENSHOT`、`PI_DESKTOP_USER_DATA`（隔离用户数据）、
  `PI_DESKTOP_OPEN_TERMINAL`、`PI_DESKTOP_COMMIT`、`PI_DESKTOP_EVAL`（驱动输入并回读 DOM）。
- 不发起付费模型推理；交互数据用真实会话文件或可控夹具。
- 主进程/协议改动必须遵守 `AGENTS.md` 的约束（LF 分帧、id 关联、扩展弹窗 id）。

## 协作边界

- 共享文件（`src/shared/types.ts`、`src/main/ipc.ts`、`src/preload/index.ts`、store、i18n）由
  单人一次改完，避免并发冲突。
- 每个新面板的样式放在独立 CSS 文件（如 `terminal.css`、`session-search.css`），
  只有通用规则进入 `global.css`。
- 新文案先写英文 key，再在 `src/renderer/src/lib/i18n.ts` 补 zh-CN；缺 key 时回退英文。
