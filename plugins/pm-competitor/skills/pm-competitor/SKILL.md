# 竞品情报：为决策服务，而不是为资料收集服务

竞品分析的产出不是“对手有什么”，而是“我们接下来要做什么决定”。先写决定，再选竞品，再收集证据，最后才做表。

## 1. 先定义决策与读者

在开始任何收集之前，用一句话写下：

- **决策**：这次分析要支持什么？常见四类：定位（主打哪个差异点）、定价（价格带与套餐）、赢单策略（销售怎么打）、路线图（哪些能力必须补）。
- **读者**：CEO/销售/市场/产品团队？不同读者需要不同颗粒度。销售要的是异议应对话术，CEO 要的是市场格局与取舍。
- **成功标准**：分析完成后，哪个决定会改变？如果答案不会改变任何决定，先别做。

把“竞品分析”当成一个没有决策的文档，是最大的浪费。

## 2. 选择竞品集合

不要只列最知名的三家。一个完整的集合通常包括四类：

| 类型 | 定义 | 例子 |
| --- | --- | --- |
| 直接竞品 | 同一类产品、同一类客户、同一个预算池 | 同为 AI 客服 SaaS 的 A、B |
| 间接竞品 | 用不同方式解决同一问题 | 外包客服团队、传统呼叫中心 |
| 替代方案 | 客户自己动手的方案 | Excel、自建脚本、内部工具 |
| 维持现状 | 客户选择“不做” | 继续忍受现有流程 |

对每个竞品写下：为什么它在集合里、它最可能抢走哪类单子。竞品数量建议 3–6 个：少于 3 个容易漏掉替代方案，多于 6 个会让矩阵失去焦点。

## 3. 证据分级与日期

**证据等级（从高到低）：**

| 等级 | 来源 | 可信度 | 使用方式 |
| --- | --- | --- | --- |
| 1 | 公开文档：官网产品页、帮助中心、开发者文档、财报、公开演讲 | 高 | 可直接引用，注明链接与日期 |
| 2 | 官方定价页：套餐、价格、计费单位、折扣政策 | 中高 | 引用前确认地区、币种、税与有效期 |
| 3 | 客户访谈：赢单/输单复盘、客户原话 | 中（需交叉验证） | 注明访谈对象角色、日期、样本量 |
| 4 | 传闻：销售口述、匿名消息、社交媒体 | 低（仅线索） | 只能标为“待验证”，不能写进对外材料 |

规则：

- **每条结论必须带来源和日期。** 没有日期的事实默认过期。
- 资料超过 90 天要重新核对，尤其是定价页和产品功能。
- 同一个结论尽量有两个独立来源；只有一个来源时，明确写“单一来源，待验证”。
- 把“事实”和“判断”分开写：事实带来源，判断带假设。

## 4. 功能评分 rubric

使用 `pm_competitor` 的 `action=matrix`。评分是 0–5 分，必须有明确锚点：

| 分数 | 含义 |
| --- | --- |
| 0 | 没有该能力 |
| 1 | 只有概念、路线图或新闻稿 |
| 2 | 早期可用，限制明显（内测、仅大客户、仅单地区） |
| 3 | 可用但一般，能满足基本场景 |
| 4 | 强，明显优于多数竞品 |
| 5 | 市场最佳，客户会为此选择它 |

**权重规则：**

- 权重代表该功能对“目标客户购买决策”的重要程度，不是对我们团队的重要程度。
- 权重用 1–5 的整数或简单小数，并在表格外写出理由。
- 只有 1–2 个功能权重特别高时，要在报告里解释为什么。
- 如果某个功能对所有竞品都是 5 分，它区分不了任何东西，权重应调低或删除。

**每格评分都要有证据**：在 `FeatureRow.evidence` 和 `FeatureRow.evidenceDate` 里写来源与日期。没有证据的格子标 `[待补充]`，不要凭印象打分。

## 5. 加权总分的局限

加权总分 = Σ(权重 × 评分) ÷ Σ(权重 × 5) × 100，只是把一张表压缩成一个数字。它一定会掩盖：

- 权重是谁定的、为什么这样定；
- 评分是文档事实还是销售印象；
- 功能之间的依赖关系（单点强不等于方案强）；
- 服务、生态、品牌、合规、迁移成本等表外因素；
- 不同客户群对同一功能的权重差异。

因此：

- 永远同时展示原始评分表、权重理由和证据日期，不要只给总分。
- 总分接近（差距 < 5 分）时，不要宣称“我们领先/落后”。
- 给总分加一句限定语：“在本表所选功能和权重下”。
- 用客户访谈和赢单/输单记录校准权重，而不是用内部会议。

## 6. 作战卡结构（battlecard）

使用 `pm_competitor` 的 `action=battlecard`，七段缺一不可：

1. **他们赢在哪里**：目标客户画像、决策链、最常赢的场景。用赢单/输单记录验证，不要写“他们品牌强”这种空话。
2. **我们为什么赢**：可验证的差异点，最好对应到客户的评估标准。
3. **地雷**：不要在对方最强的战场硬碰；列出我方短板，销售不得承诺无法兑现的能力。
4. **异议处理**：客户最可能说的 3–5 句话，以及“承认前提 → 澄清场景 → 给证据”的回应框架。
5. **证据点**：客户案例、基准测试、第三方评测、ROI 测算，全部带日期与口径。
6. **该问的问题**：帮助销售判断这单能不能赢的发现式问题，而不是背产品介绍。
7. **近期变化**：近 90 天的产品发布、定价调整、融资并购、关键人事；没有就写“待补充”，不要编。

作战卡是内部讨论底稿，不是对外宣传材料。

## 7. 定价对比口径

使用 `pm_competitor` 的 `action=pricing`。对比前统一：

- **币种**：不同币种不换算就并排比较，是常见的误导。
- **计价单位**：席位、账号、用量、企业包干不能直接比；先折算到同一口径。
- **周期**：月付、年付、季度付要折算年价，同时注明是否含折扣。
- **包含内容**：功能包、额度、支持等级、SLA、实施费、最低消费。
- **税**：含税/不含税要写清楚。

表格之外，写一句“报价来源与日期”，并注明哪些价格是官网标价、哪些是销售口头报价。

## 8. 输出格式

默认中文 Markdown：

1. **先结论**：3–5 条，直接回答“所以我们要做什么”。
2. **再表格**：功能矩阵、加权总分、定价对比各一张，列名清晰。
3. **再证据**：每条关键结论带来源与日期；单列“证据与日期”一节。
4. **最后不确定**：列出仍不确定的假设、需要谁去验证、截止日期。

避免：大段形容词、没有出处的“行业领先”、只给总分不给明细、把传闻写成事实。

## 9. 伦理与合规

- 只使用公开渠道或合法获得的资料。禁止使用对方机密文件、窃取的报价单、未公开客户名单、前员工带来的内部资料。
- 不冒充客户骗取报价，不违反保密协议，不进行商业贿赂。
- 不贬低对手：陈述可验证的事实，让客户自己判断。
- 引用第三方评测要注明方法、样本和时间；不能断章取义。
- 涉及个人信息时做匿名化处理（客户 A、某制造业企业）。
- 内部使用与对外使用的版本要分开：对外材料删掉传闻、未证实信息和内部人名。

## 10. 质量检查清单

提交前逐条检查：

- [ ] 写清了这次分析支持的决策和读者？
- [ ] 竞品集合包含直接竞品、间接竞品、替代方案和维持现状？
- [ ] 每个功能都有 0–5 分、权重和证据/日期？
- [ ] 权重理由写在表格外，而不是只藏在数字里？
- [ ] 加权总分附近有“它掩盖了什么”的提醒？
- [ ] 作战卡七段齐全，且异议话术是“承认 → 澄清 → 证据”结构？
- [ ] 定价表统一了币种、单位、周期，并注明税与折扣？
- [ ] 每条关键结论都有来源和日期？
- [ ] 传闻被明确标为待验证，没有进入对外材料？
- [ ] 最后写了仍不确定的地方和下一步验证计划？
